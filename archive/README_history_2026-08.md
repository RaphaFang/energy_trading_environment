### (d) 成本函數合併成一條(`chp._cost_coeffs`)

```
c = (p_fuel + ef·p_CO2 + θ)·F + vom_e·P⁺ + vom_th·Q − p_el·P + (τ+κ)·P⁻
```

燃料別靠**參數歸零**切換,零分支。P⁺/P⁻ **不需要 `max()`** —— 賣電與買電本來就是不同的
變數區塊,方向在建模時已知,所以 `max(−el,0)` 在建矩陣時就算掉了,LP 仍是線性的。
**有等價性 self-check**:vom=0、稅費=0 時逐項還原重構前那五行係數。

### (e) 背壓機組 = **一個界**,不是一套新矩陣

```
加一條  P − Cb·Q ≤ slack
slack = p_max  →  恆成立不綁(P≤p_max 且 Cb·Q≥0)= 抽汽式保有可行域面積
slack = 0      →  與既有的 P ≥ Cb·Q 夾成等式 P = Cb·Q = 退化成一條線
```

約束矩陣結構完全相同,**機組型式是參數不是分支**。
🔴 **背壓表的 `Cv=1.0` 必須歸零**(N/A 哨兵值)—— 照抄會讓容量線變成 `P + 1.0·Q ≤ P_max`,
憑空砍掉大半熱出力。`dea.plant_params` 已處理並有 assert 鎖住。

**順便解掉容量 NOT_FOUND**:`P = Cb·Q` ⇒ **`P_max = Cb · Q_max`** —— 背壓式的電容量是
熱容量的**後果不是獨立自由度**(`dk2_fleet.derived_mw_e()`,只對背壓式成立)。

🔑 而且這個否定比看起來更強:線性下界沒有 0/1 開關 = 機組**完全不能停機**,

🔴 **兩個 confound 還沒排除**(見 `STATUS.md` §8.6):
① 尖峰鍋爐是**無上限懲罰項**不是有容量的機組 —— 無上限又無啟停成本的鍋爐在 LP 裡是

測過,ρ 只從 −0.500 動到 −0.506、上限僅 1.2% 小時綁到 → **檢定太弱,排除不了**。

② 用背壓垃圾原型代表 64.6% 是生質抽汽的車隊。

**三個診斷各擋掉一種假象**(細節見 `STATUS.md` §8.1):日固定效果擋季節性、
移除「月×時」形狀擋兩條固定曲線對齊、日總量拆「開多少 vs 何時開」。
⚠️ 上一輪那個「垃圾與熱電高價時出力更高」的直覺**在同日內是反的** —— 季節性陷阱又出現一次。

## ⑥ ✅ agent 的定義:**2026-08-15 使用者定案**

### ⑥.1 一個 agent 是什麼

> 使用者原話:「模型要做的是我主要賣電但同時有熱水場,你要最大化收益兩者,
> 這就是一個 agent 應該做的。」

|                | 定案                                                                     |
| -------------- | ------------------------------------------------------------------------ |
| **agent = 誰** | **廠級業主**(HOFOR、Ørsted、ARC、Vestforbrænding、ARGO)                  |
| **它在做什麼** | 手上有一座 CHP,**電賣到電力市場、熱送進熱網**,目標是**兩邊收益合計最大** |
| **目標函數**   | **利潤最大化(電+熱合計)**,不是成本最小化                                 |

⚠️ **這取代了先前討論裡「市政成本最小化、商業利潤最大化」的混合版本** ——
使用者用上面那句話把它統一成全部利潤最大化。
📌 **對現在跑得動的兩台其實沒差**:ARC/ARGO 燃料成本是負的,不管叫成本最小還是
利潤最大都是全開(已量到 97.6–99.8%)。**這個假設要到生質那三台解鎖後才會真的影響結果。**

### ⑥.2 🔑 但熱不是 agent 自己說了算 —— **兩層結構**

**DK2 的熱是 Varmelast 統一調度的**(見 ②(a):`Varmeplanen skal opfylde
fjernvarmeselskabernes daglige prognose for varmebehov`)。所以一個 agent 的決策是兩層:

```
第一層  它拿到多少熱的量  ← 由 Varmelast 按成本排序決定
                            agent 能影響的是**自己的成本有多低**,不是自己的量
第二層  拿到熱之後電出多少 ← 被機組型式綁住(背壓幾乎沒得選、抽汽有餘裕)
                            **剩下的那點自由度 = 這個 agent 的「彈性」**
```

🔑 **核心假說活在第二層**:熱需求高的時候,每一家的那點自由度**同時**被壓縮,
而那正好是系統最需要彈性的時候。

✅ **好消息:這個結構不需要內生價格或賽局均衡** —— 就是「N 個業者各自解自己的問題

- 一個中央熱量分配」。**電池線就是死在內生價格上的**(雙算無解,見 `BATTERY_TRACK.md`),
  這條路避開了它。

### ⑥.3 還沒定案的(只剩這個)

- **回測窗口**:資料上 2021-01 → 2026-07(5 個完整冬天),但 2021–2024 需要生質價。
  ⚠️ **不要拿 2025 的價格鋪滿所有年份** —— 已量化:2021 木片是 €18.9–23.3、
  2025 是 €34.0–38.8,**鋪滿會高估 55–90%**(見 `DATA.md` §8)。

### ✅ Phase 1 — **2026-08-15 完成**(生質價用假定值,四台機組活過來)

**這不是「把熱側做得更完整」,它是核心假說能不能被檢驗的開關。** 理由:

「彈性」在 CHP 裡的定義是**「熱送出去的量固定時,電還能不能調整」**,
而這**完全取決於機組型式**:

| 型式     | 機組                       | 電熱關係                    | 有沒有彈性                   |
| -------- | -------------------------- | --------------------------- | ---------------------------- |
| **背壓** | ARC、ARGO、Vestforbrænding | `P = Cb·Q`,電是熱的固定倍數 | **完全沒有**。熱定了電就定了 |
| **抽汽** | Amager、Avedøre、Køge      | 電熱可互換,有一個可行區間   | **有** —— 彈性只在這裡       |

🔴 **現在跑得動的 ARC 與 ARGO 兩台都是背壓** → 今天蓋多 agent 層,會得到
**兩個幾乎相同、而且完全沒有彈性的 agent**,「彈性同時消失」這個假說
**在數學上就不可能被檢驗**。

✅ **卡住的那三台剛好全是抽汽式** —— DK2 的彈性幾乎 **100% 在它們身上**,
而且燃料成本為正(才會對電價有反應)、業主不同(才有「多個業者」可言)、佔供熱 **64.6%**。

**做了什麼**(使用者授權「先設一個假定值,不要再花時間算」):

- `assumptions.BIOMASS_ASSUMED_EUR_MWH` —— 2021–2025 逐年,**存區間的兩端**
  (丹麥海關 / 瑞典熱廠),數字是從 `new_data/fuel/` 的原始資料算出來的**不是編的**
- `assumptions.biomass_fuel_price_assumed()` —— **刻意跟原本那支分開命名**。
  原本 `biomass_fuel_price_eur_mwh()` 對 <2025 拋 `KeyError` 的行為**完全不動**
  (它擋的是「有人偷偷用單一值回填」)→ **不會有人不小心拿到假定值**
- `assumptions.ASSUMED` —— 新的一類警告(**有值但值是假定的**,與 `PLACEHOLDERS` 的
  「值是 0」性質不同),每次跑都印
- `chp.dk2_plant()` **擴充到抽汽式**:背壓用 `derived_mw_e()` 反推、
  **抽汽用 `dk2_fleet` 查到的 MW_e 真值**(抽汽有凝汽尾,電容量是獨立自由度,不能反推)
